# Roadmap

Reviewed 2026-11-26. Current released version: `0.6.0`.

The `0.5.0` release work is prepared. This roadmap tracks only work that has
not shipped yet, grouped by delivery horizon. Version headings are planning
targets, not release date promises.

## Direction

- Preserve safe, structured debugger workflows before expanding the tool
  surface. Raw GDB access remains opt-in.
- Keep stdio startup lazy and keep remote HTTP deployment explicit,
  authenticated, and isolated.
- Prefer reproducible workflows, bounded responses, and actionable failures
  over client-specific presentation features.
- Require deterministic protocol tests for every public contract change and a
  live-GDB test where behavior depends on GDB itself.
- Move completed work to `CHANGELOG.md`; do not retain checked tasks in the
  active roadmap.

## Now — 0.6.0 deployment hardening and contract automation

### P0: Security and contract gates

- [ ] Complete an end-to-end pre-release HTTP security and proxy review.
  - Exercise malformed authentication, forwarded host/origin handling,
    disconnects, concurrent HTTP clients, session isolation, and unsafe-mode
    combinations through the Streamable HTTP transport rather than direct calls.
  - Keep reverse-proxy guidance vendor-neutral and verify every public-listener
    requirement against an integration fixture.
  - Acceptance: the threat model and tested deployment behavior agree, and no
    rejected request starts GDB or leaves a session or child process behind.

- [ ] Enforce committed MCP contract snapshots in CI.
  - Check in a baseline snapshot generated by `scripts/check_mcp_contract.py`
    covering initialization capabilities, prompt/resource metadata, and complete
    tool input schemas across discovery profiles.
  - Acceptance: CI prints a readable contract diff and fails on unapproved
    breaking changes.

### P1: Live workflow verification

- [ ] Add live-GDB CI fixtures for relocated source and split-debug binaries.
  - Compile fixture executables with `-fdebug-prefix-map` and `objcopy
    --only-keep-debug`, then verify `gdb_apply_init_profile(profile="debug_info")`
    against live GDB and unavailable symbol-server fallbacks.
  - Acceptance: live compatibility tests pass on Ubuntu 22.04 and 24.04 with
    actionable fallback diagnostics when `debuginfod` is unavailable.

- [ ] Wire `scripts/run_eval_harness.py` into CI and add live-GDB baselines.
  - Track tool-call count, serialized bytes, estimated tokens, elapsed time,
    and cleanup state across CI runs alongside the existing fake-GDB baselines.
  - Acceptance: workflow or response-budget regressions fail CI per scenario.

- [ ] Add end-to-end transport tests for operational log redaction.
  - Verify `GDB_MCP_LOG_LEVEL=debug` over real stdio JSON-RPC leaves stdout
    uncontaminated while redacting inferior arguments, tokens, and env values.
  - Acceptance: stdio interoperability tests pass with `debug` logging enabled.

## Next — 0.7.0 parser corpus and workflow depth

### P1: Parser and workflow robustness

- [ ] Broaden the GDB/MI compatibility corpus from additional distro GDB builds.
  - Capture sanitized transcripts from newer GDB releases and expand property
    tests for async record ordering and C++/Rust template output.
  - Acceptance: every parser fix adds a minimized fixture with bounded parse
    time and memory.

- [ ] Improve multi-thread and async-event ergonomics in compact context tools.
  - Evaluate bounded thread-summary hints in `gdb_context` without regressing
    default response budgets.
  - Acceptance: response-budget checks stay green and existing response shapes
    remain backward-compatible.

- [ ] Add multi-session concurrency stress tests under Streamable HTTP.
  - Exercise parallel `gdb_run_and_context`, cancellation, and `prune_idle`
    under concurrent HTTP sessions.
  - Acceptance: zero orphaned child processes or cross-session state leaks.

## Later — ecosystem options

These items require evidence from users or maintainers before they are promoted
to a release milestone.

- [ ] Evaluate a maintained Nix flake/package for reproducible GDB, gdbserver,
  compiler, and optional rr dependencies.
- [ ] Evaluate cross-architecture remote debugging with explicit architecture,
  sysroot, and multiarch-GDB compatibility reporting.
- [ ] Evaluate additional MCP client and authorization-provider fixtures when
  they reveal protocol or deployment behavior not covered by the current
  stdio/Streamable HTTP harness.

## Non-goals for the current roadmap

- Turning `gdb-mcp` into a general shell or enabling unsafe tools by default.
- Adding more thin wrappers around raw GDB commands without a demonstrated
  agent workflow.
- Claiming local macOS or Windows debugging support without dedicated CI and
  maintainership.
- Building an IDE, terminal UI, or hosted multi-tenant debugging service.

## Completed milestones

- July 2026 baseline (`66736f2` and focused follow-ups): modular tool domains,
  shared responses, cancellation cleanup, resources, compact profiles, bounded
  and paginated outputs, rr and remote/core workflows, packaging, parser tests,
  cookbooks, and compatibility documentation.
- July 2026 protocol and reliability follow-up (`51c999a`, `4a17615`, and
  `e52ae61`): lazy static resources/prompts, HTTP safety, workflow prompts,
  progress, initialization profiles, redacted bundles, real discovery profiles,
  opaque cursors, token budgets, live compatibility CI, and MCP/release-install
  interoperability checks.
- November 2026 `0.5.0` release: `mcp>=2.3.0,<3` (`MCPServer`) migration,
  standardized `ErrorResponse` codes, idle-session TTL and dead-session pruning,
  `debug_info` initialization profile, `elf` / `inspection_format` split with
  deduplicated analysis calls, MI parser and `checksec` hardening, opt-in
  redacted stderr observability, MCP contract diff engine, and deterministic
  scenario evaluation harness.

Release-level detail belongs in `CHANGELOG.md`; the Git history remains the
source for implementation-level detail.
